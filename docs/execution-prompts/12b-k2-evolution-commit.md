# K2：应用与回滚可恢复

你是本票实现主代理，工作区和检查沿用[公共合同](README.md)。修改前保存基线；核对唯一计划 K1 已验收。本文件是 K2 的完整合同，只读当前 guide 与相关代码。修复 `evolution.apply/rollback` 先写生产、后记账导致崩溃后无法对账的问题，不扩候选种类。

## 固定行为与归属

1. `evolution` 是应用/回滚意图、内容身份和完成记录的唯一所有者。保留现有人审和晋升证据检查；在人审与写前重检之后，先持久化操作意图，再写生产，最后记完成。意图绑定 proposal、方向、批准来源、目标、前后内容身份及可恢复的字节来源，不信任内存 promise 或模型传的 approved。
2. 单文件用同目录临时文件、必要 flush 与原子 rename 替换，账本遵守既有持久化约定。不要直接截断生产文件。写失败不记完成；临时文件不是已应用结果。
3. 显式启动/恢复先对账未完成意图：生产是预期旧内容则补做同一操作，是预期新内容则仅补完成记录；既非旧也非新、来源缺失或不可验证就具名停止，禁止覆盖第三方变化。不自动开新 proposal、重新实验或重复扣实验费用。同一意图重试/重启只得到一个领域完成结果。
4. 应用和回滚共用这一提交规则。rollback 只从本提案已应用的新内容恢复其原基线；后续提案已改变同一目标时拒绝旧 rollback，不覆盖新版本。按生产目标串行重检、写入和记账，覆盖不同 proposal 的竞争；已有单进程部署约束保留，不建分布式锁。
5. 未完成意图涉及的目标不能被新 Run 加载。宿主接线负责在 provider 准入/graph 激活前对账；关闭 Evolution 工具不豁免生产一致性检查。只阻断受影响目标，不禁止读取诊断；旧已绑定 Run 不热换版本。状态查询纯读，不顺带应用/回滚。

删除原先裸写后 append 的生产路径。不要另建事务包、通用事务回调框架、补偿策略注册表、后台重试队列或 helper 转发层。只承诺当前单文件 Skill；K3 随后扩同一提交机制的对象范围，本票不能以 K3 为由省略现有单文件恢复。

## 验收

| 编号 | 必须证明的结果 |
|---|---|
| K2-1 | 合法人审/双侧证据下 apply、rollback 各只生效一次；拒绝批准、候选/基线漂移时零生产修改。 |
| K2-2 | apply 和 rollback 各在意图已落盘、替换前、替换后完成记录前、完成后重开：生产只能是可验证完整版本；恢复结果唯一，重试可读，无人工补账。 |
| K2-3 | 意图未结时真实 provider 准入拒绝；恢复后可加载，工具开关 off 不旁路。查询零写，已绑定 Run 版本不变。 |
| K2-4 | 外部篡改、来源丢失具名停止并保留意图；两个 proposal 竞争同一目标只有匹配当前基线者可写。应用第二提案后回滚第一提案必须零写。 |
| K2-5 | 新格式重开及当前已应用对象回滚有效；九工具与服务使用唯一提交入口，无旧裸写路径。构建与公共回归通过。 |

故障测试跨真实文件、账本、服务与准入；明确进程退出注入和普通异常的区别，不用 mock write 返回失败代替“生产已写但记录未写”。无真实模型费用。

需要改持久格式就单版本切换，拒绝旧写入/旧 reader，不建在线迁移。切换真实旧账前保存原字节；未闭合 applied/意图先由对应旧版处置，不能删账掩盖生产状态。测试使用临时 fixture。

更新主 guide、唯一计划 K2 状态及必要持久化记录，只保留一份交付证据。提交本票和外层指针，最高填待验收并停止；审核后派 K3。

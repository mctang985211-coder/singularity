# 单票任务派发模板与示例

用途：补救后的单票建设，也可用于计划明确列出的一个交付组。它不改变[唯一执行表](../2026-09-20-vrtc-code-change-plan.md)，合同已定不表示前置已通过。先填任务事实与验收，再派发；不需要把所有专项文档全文复制进 prompt。

限制的是无依据的扩展、反复选型和重复劳动，不要求 agent 少理解代码或隐瞒缺陷。Prompt 不能保证工程质量，最终仍检查实际 diff、调用方、验收与停止条件。

## 直接派发入口

以下入口只在当前票没有待审核交付时交给实现主代理。票据交付后改用[进度审核 prompt](progress-review-and-dispatch.md)，审核前不自动连续施工。第 8 项 R1 与第 8a 项 R3 均已验收，首个可派票是第 9 项 A2+A1；不要重复派 R1/R3。完成轮 1、2 的失败与归档 S3 的 `inconclusive` 仍是只读历史证据。

```text
你是 Singularity 本次实现主代理，工作区：
/home/ROXY/code/bb_work/harness/packages/singularity
外层仓库：/home/ROXY/code/bb_work/harness

先读 docs/singularity-harness-guide.md 的当前状态及 §1.4–1.5，
docs/2026-09-20-vrtc-code-change-plan.md 的唯一执行表，
docs/execution-prompts/README.md 的公共合同，以及本模板的实施约束。
只执行唯一表中首个未完成的有效票号；跳过已注明合并的历史编号。
前置不满足就报告阻塞；已有交付待验收时只指出应走进度审核，不接下一票。
若当前为 R1，先核对计划中的完成轮记录；R1 已验收，不重复修判据/账目或重判归档轨迹。
当前直接派发入口对应第 9 项 A2+A1；按计划 D/E 节及[专项 prompt](09-a2-a1-context.md)执行，不重做 R3。
进度审核尚未完成时停下，交给 progress-review-and-dispatch.md。
审核提出新的定向返工合同时，才按该合同实施，不沿用旧实验预算。
其他票只读本模板合同索引所指的段落及必要源码，按既定合同实施。

修改前保存 Git 基线。先简列本票交付、所有者、验收编号与内部交接顺序，
随后执行，不再重做架构选型，不建设后续票、不预建假想故障处理。
可委派子代理；每次每人一个子目标，使用下方“子代理任务格式”。
接口有依赖先交接，再派消费者；你负责集成、全量检查、独立复核和 guide，
不能将整个交付组原样转派，也不能将内部提交当成整票完成。

完成本票所有验收及公共检查后，更新主 guide、唯一计划和受影响合同，
提交改动及外层子模块指针，报告证据、未覆盖项和提交号后停止。
全部满足后填待验收；仍有合同失败就保留返工，证据未齐明确列缺项。
由进度审核确认后再派下一票；缺必要实跑证据不得填已验收。
不推送、不部署，不擅自新增模型费用或复用旧票的实验预算。
```

## 可填写 Prompt

```text
你是 Singularity 本票的实现 agent。完成下列有限行为、验证并同步文档，验收通过后停止。

工作区：/home/ROXY/code/bb_work/harness/packages/singularity
外层：/home/ROXY/code/bb_work/harness
先读主 guide 当前状态及 §1.4–1.5、建设计划唯一执行表与本票合同、
docs/execution-prompts/README.md；其余历史与专项内容按本票需要读取。

【任务】
票号/名称：<唯一执行表中的一票或交付组>
前置证据：<已验收提交、计划记录>
冻结合同：<按上方合同索引填写对应段/返工补充与验收编号，不委派重新选型>
当前问题：<具体输入/调用者/入口、现在结果、期望结果及证据位置>
本票交付：<一句话描述用户或调用方可观察的新行为>
主要落点：<现有模块；不是禁止修改必要调用方的文件白名单>
职责归属：<事实所有者 / 行为所有者 / 工具与 prompt 消费者 / 迁出与删除位置>
既有复杂度：<本票涉及的 400 行以上文件；逐个写保留/删去/迁出/包内拆分及依据，不扫描无关全仓>
依赖方向：<谁消费谁；不得为了接线让 task/runtime 反向依赖 context/review/evolution>
范围外：<容易顺手扩展的相邻功能，不列无关的禁止清单>
验收：<编号列明输入、外部结果及关键副作用；包含合法正例和必要反例>
实验资源：<需要真实模型时填写已有连接及总预算；不需要则写无>
完成条件：<必需的协议/真实运行证据；若缺授权，哪些可先做、缺什么不能验收>
委派安排：<不委派，或每个子代理的一项子目标、接口依赖、验收与停止点>

【实施约束】
1. 核对前置、工作区与 AGENTS.md，修改前按公共合同建立 Git 基线。
   用简短说明列出当前行为差异、复用落点和验收对应，随后实施。
   已有方案能满足合同就沿用；只有遇到具体阻碍才比较替代方案。
   工具输入、可信绑定、候选支持范围和恢复入口按冻结合同落实；
   私有文件/函数组织自主决定，不改变记录所有者、权限或验收语义。
   真有接口冲突，先返回具体阻碍与最小调整，不新增一套竞争协议。
   允许必要的源码/API 查证，不默认开展全仓审计、外部调研或多方案设计。
   委派遵守公共合同的“子代理派发粒度”：一人一次一个可独立验收目标，
   主代理负责集成、全量检查与 guide；只传相关材料路径。上下文紧张时
   先交接改动、证据和剩余项，再续跑剩余目标，不整票重复派发。

2. 每项新增行为、状态、配置、导出或依赖，都要能对应本票验收要求，
   或当前支持路径的具体缺陷及其调用方。证据可以是失败测试、真实轨迹，
   也可以是源码中明确可达的错误路径；不必等生产事故发生才修复。
   “未来可能有用”不足以新增框架、兼容层、重试/回退或持久字段。
   必要的输入校验、权限、取消、恢复及旧数据合同不能以简化为由跳过。

3. 新发现的问题分开处理：本票及所依赖路径的缺陷先修复并重验；
   无关缺陷简记位置与影响，不顺手修复；仅设想的未来场景不进代码，
   也不自动列成必建任务。若需要改变目标、已接受合同或授权范围，
   说明具体阻碍与最小调整，保留未完成状态，不能自行扩张或降低验收。

4. 优先复用现有模块。为当前可见的重复职责或一致性缺陷才做重构，
   不为文件行数、命名偏好或假想扩展性拆模块。补丁连续叠加时回查
   共同原因和职责归属，不对每个症状再加一层分支；不要求为此全盘重写。
   普通实现取舍自主决定，不把上述依据要求变成逐项向用户申请许可。
   工具名字含 task 不代表实现属于 task。跨来源上下文归 context，通信归
   agent-runtime/DSH，候选与评估归 evolution；终态与写闸仍归 task-runtime。
   迁移同批替换消费者并删除旧实现，不以新包外壳保留两个事实源。
   400 行触发职责检查，不要求每个文件低于该数。移走整项规则与测试，
   保持原子提交和有状态协议的唯一所有者；不创建共享可变的 RuntimeInternals，
   不用一层同名转发掩盖原大模块仍决定所有行为。仅测试使用的便捷流程
   放测试支持层，测试仍穿过真实生产入口；不为保留它新增生产消费者。
   不预设 Agent 可能遇到的业务失败全集；新问题由 Agent 取证、实验和提出
   候选，框架执行通用契约/权限/预算/验证/批准规则，不硬编码修复策略。

5. 验证与变更风险匹配：先跑能定位问题的检查，收尾完成公共合同和本票
   必跑项。测试通过后，只有新改动、新失败或明确未覆盖风险才扩大/重跑；
   不为获得更多绿色次数反复全量测试，不用放宽超时代替竞态修复。
   无新证据时不反复推演同一担忧；针对实际疑点取证或说明阻塞。
   有针对性地检查最终 diff 中多余的分支、字段和测试，不建立评分平台。

6. 满足验收、必要检查通过、相关缺陷关闭且 guide 同步后停止。
   不继续下一票，不追加“顺手优化”。达到时间/模型预算但未完成时如实
   报告剩余工作，不宣称完成，也不删检查换取按时交付。
   子目标完成只是交接；整票满足合同才交付待验收，仍有失败保留返工，
   进度审核后才可填已验收。
   A6 不得以 scripted 接线代替 EVO-1 真实 Agent 生成候选的证据；
   缺模型授权先完成可做的机制工作，明确保留实跑缺项，不默认为可跳过。

【交付】
同步 docs/singularity-harness-guide.md 的当前事实和相关缺口，以及
docs/2026-09-20-vrtc-code-change-plan.md 的本票状态、证据与下一项前置；
仅更新受影响专项合同，事件变化记录兼容性。不要新建竞争路线图。
报告行为变化、验收结果、已知限制、基线/交付版本与 Git 状态；
独立复核按公共合同执行，未做不得写已通过。不推送、不部署。
```

## 子代理任务格式

仅供已授权的委派，主代理一次填一个子目标。D/E/F 的内部交接仍可能跨多个职责；若某一步同时包含通信、runtime、context 三项实现，应按接口先后继续拆开交接，不改整票验收边界。无需因此新建子任务文档或进度平台。

```text
你负责本票的一个子目标，不负责整票。你不独占工作区，不回退他人修改。
目标及基线：<一个可观察行为；已交接提交/接口>
必要输入：<对应合同段、调用入口、相关测试；不附全部指南与聊天>
修改所有权：<你负责的模块/文件；共享接口由谁交接>
验收与停止点：<对应验收编号的这部分，合法/拒绝结果、定向检查>
范围外：<相邻但属于下一子目标的行为>

按已定接口实现并更新必要调用方，不自行新增状态机、包或修改验收。
若需要他人负责的接口，先交接具体变更需求，不在共享文件并行改同一处。
发现合同冲突返回证据与最小调整，不自行选新架构或削弱正确性。
完成后只回报改动、接口、已跑检查及结果、剩余/阻塞和未结束进程。
不跑整票全量、不改共享 guide、不宣布整票完成。
上下文不足先交接这些内容，续跑只做剩余目标，不从头审计整票。
```

## A2 + A1 填写示例

下面替换模板的“任务”部分，其余约束沿用。**R3 已验收，第 9 项 A2+A1 可派发**。范围以[唯一计划 D/E 节](../2026-09-20-vrtc-code-change-plan.md)为准；主代理只将内部一个子目标委派给单个子代理。

```text
票号/名称：A2 + A1，Agent 状态上下文（一个交付组）。
前置证据：第 8 项 R1 与第 8a 项 R3 已验收；核对唯一表的交付提交与审核记录。
冻结合同：计划 D 的读取表/A2-5、E 的恢复顺序，保留 A2-1–A2-4 全部验收。
当前问题：worker 只有本人契约和一层 handoff，全树列表缺相关性组织；
深层 worker 需要根约束、本人贡献和依赖验收，压缩后仍需追溯来源。
本票交付：少量必要上下文进入真实模型请求，项目概览和证据/历史可按引用
主动读取；两者使用同一 context 读取实现，同 graph 可读，跨 graph 拒绝。
职责归属：新 context 包负责投影/相关性/引用/读取域及 DSH 装配接线；
task 保留事实，task-runtime 保留准入/写闸/恢复，agent-runtime 保留身份/
稳定角色政策；agent-singularity 的模型工具只适配，不承载投影实现。
迁移删除：task_read/status 跨记录渲染、handoff 的上下文渲染迁出旧实现；
普通/replay/恢复接线一起替换。runtime 不导入 context，稳定 handoff 数据
仍由 runtime 保存；DSH system-prompt/assemble 异步钩子负责读取时机。
现有 runForSession 不是纯读：先将恢复接到 graph 的显式激活/恢复流程，
首请求前完成恢复与写闸初始化；context 仅从可信 graph/store 和快照读事实。
activate 等待对账/闸/driver 登记，不等批次执行；create 同门，不能重复 adopt。
直调执行未 ready 具名拒绝；读取只显示状态，技术失败不吞成 ready。
固定 task_read、task_status(scope=related|graph) 与 context_read(kind/ref)；
关闭原始跨 Session 工具的有效 grant 和 pre-execute 旁路。无 Run reviewer
用现有 ledger，spawn 的 beforePrompt 在图发布后、首输入前确认持久绑定。
迁移 contract.ts、renderRunBinding 和 root-store 视图；保留内容校验及准入。
范围外：新 memory 数据库、全局知识索引、group ACL、A4 问答、任务领取、
通用动作引擎、固定 supervisor 查因流程；不用新字段替代已有引用。
验收：
A2-1 三层 worker 的真实请求含根目标/硬约束、本人完整契约与贡献；
      兄弟依赖的验收和证据可读，无关历史默认不推但同域可按需取。
A2-2 相同 cwd 的不同 graph 不互读；原始 Session 工具同批收紧，不能
      绕过 context；无 Run 的 reviewer 按实际委派域读取，不自动成为 root。
A2-3 压缩/重启后从事实源恢复；replay 不串根；未激活/等待/终态准确，
      缺失/超限/省略明确；重复装配不累加，原动作检查不被读取或提示改变。
A2-4 冷/热查询与 prompt 装配零生命周期副作用；重启后首个写工具已受闸，
      普通与 replay 首请求不依赖 spawn 返回后才建立的内存绑定；R2 反例保留。
A2-5 三个入口按冻结 schema 工作；无 Run reviewer 首请求可读委派目标，
      绑定落盘失败零模型输入；存储/恢复失败阻断新执行但诊断仍可读，
      重复激活不重复 driver，waiting_children 恢复不自锁，直调不能旁路。
委派：依次交接恢复/纯读分离、读取投影、工具/请求装配和迁移、独立组合验收；
      主代理负责包装配、集成、全量检查和指南，整组通过后再进入 A4。
实验资源：本票确定性协议验证无需真实模型；不据此声称探索效率提升。
```

查询零领域写入；DSH 将实际模型上下文记入 Session 属正常可追溯记录。只显示有依据的执行限制，实际动作由原入口重检；不要求通过第二套 allowedActions 状态机证明一切动作必然成功。

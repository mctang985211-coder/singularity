# 验证规范：以公开行为与来源关联为目标

本文件是当前 TDD、spec 与门禁的唯一规范。当前改造的产品出口在 [Task 优先的领域 RSI 计划](task-first-domain-rsi-plan.md)，
接口检查表在 [tdd-seams](tdd-seams.md)。

## 1. 先合同，再 red → green

先明确功能、接口、合法转换和错误出口，再写能让当前错误实现失败的 spec，随后最小实现。
一次验证一个可观察行为；跨领域语义不明时先 grill，已确认合同与常规内部实现不另设签字流程。

公开行为包括返回值/错误、提交后的持久事实、事件顺序和对外调用。部署接口也是公开边界，不能只按包 exports 判断。
可通过持久化/运行端口使用 double；不 mock 被验证的规则，不读私有 map 或复制被测投影来生成期望值。

一个用例可以检查同一行为的多个独立后果，例如拒绝码、没有提交和没有外部副作用。
重复断言应删除；不得拆 it、合并 expect 或删关键覆盖去凑行数/密度。
重构后 spec 红，先确认公开行为是否变化；仅依赖内部结构的用例改到公开边界或删除重复，真实行为回归必须修正。

## 2. 当前必须区分的结果

| 验证目标 | 有效见证 |
|---|---|
| 执行完整性 | 正确 stdout 但非零退出不能 verified；并发/重送不改变别的 Run 的产物 |
| 调度归属与尝试 | A/B 根并存仍派发到准确父；同会话 fail 后开启下一 Run；预算耗尽停止并通知 |
| 真实依赖 | 前序 verified 后后序实际执行且使用封存产物；子 pass 不能替父 pass |
| 来源与恢复 | 当前快照与正式 receipt 各有准确 cutoff；在飞崩溃恢复同身份/提交；追加无关事实不改 receipt |
| 发布闭环 | 已提交决定、真实 Web 批准、唯一 head 更新、新 Run 的实际方法消费彼此可关联 |

检查“扫描被调用”“存在一个非 running child”“session 已打开”都不足以替代这些行为。
已有错误行为被 spec 固定时，先替换为正确合同的失败见证，不保留旧 spec 作为兼容目标。

## 3. 验证层次与停止条件

- 静态/schema/typecheck：检查边界声明、未知形状、类型与构建产物；不能证明副作用或人的批准。
- 端口 spec/集成：验证身份、状态转换、隔离、错误和重送；用最小正/负例覆盖本次改动。
- 产品探针：通过私有 profile、真浏览器/工具/进程完成 Task—Run—session—产物—判决的实际关联；不由脚本接管关键产品步骤。
- 效果实验：冻结真实基线、任务集、口径、预算和阈值，质量/成本另报达标或未达标。

改动先跑相关 spec；阶段出口跑必要回归与产品证据；最终跑完整构建/发布验收。
检查已通过且没有新修改、失败或未解决疑点时进入下一包，不反复加测或重审同一结果。
`pnpm verify` 是离线回归，不含探针；产品证据的命令与费用边界见 [standalone-dsh](standalone-dsh.md)。

## 4. 门禁与变异的边界

新增/保留门禁必须能指出独立不变量、检查入口和能让它失败的有效反例；优先加强已有探针，不复制一套探针编排。
门禁数量、测试数量、预算比值和检测器合成失败都不能代替产品证据。尺寸/密度用于审查；现有硬阈值的取舍在 W5/W9 审阅实现，
不靠改阈值、转移代码或删行为覆盖过关。无独立行为目标的重复检查和散文豁免补丁应删除。

对承重的不变量或尚有可信度疑点的检查，定向变异检验失败原因；不要求每条普通断言再配一个变异。
变异必须有效施加、正常启动，并因目标行为失败；导入/收集失败、无 test summary 或任意红灯不算见证。
变异结果保存在现有 mutation baseline，文档只保留可查入口，不复制编辑/witness/数字。
当前门禁仍强制每个变异 ID 出现在文档，context/G2 保留最短索引以符合现行检查；W9 取消手抄 ID 要求，
继续校验账本的有效编辑、运行命令与目标见证，文档链接账本即可。届时删除这些重复索引，不另建证据目录或扫描 DSL。
变异未触发先查构造、可达性和行为覆盖，不能立即删除正确规则。

## 5. 完成时清理

同次修改删除被替代实现、过期 spec/变异、无消费者配置和关联缺陷注释。
失败不可降为 stderr 后继续或成功空结果；已提交结算与后续派发失败分别报告，不能误导重送已经完成的工作。
代码注释说明当前必要约束与非显然原因，缺陷经过留在提交历史。共享工作树只提交明确拥有的文件，提交与长检查分开。

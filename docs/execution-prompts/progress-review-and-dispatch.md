# 进度审核与下一票派发指挥 Prompt

将本文件交给负责核实进度、维护指南和准备下一票的 agent。默认只审核与编写文档，不实现业务代码、不启动其他任务；需要实施时由派发者另行授权。

## 任务

你负责核实 Singularity 的实际建设进度，修正文档漂移，并按[单票模板](task-dispatch-template.md)准备下一份可派发 prompt。完成本轮审核与一份派发材料后停止，不把“准备后续工作”扩大成重做架构或实施多张票。

工作区：`/home/ROXY/code/bb_work/harness/packages/singularity`；外层：`/home/ROXY/code/bb_work/harness`。

先读 `docs/singularity-harness-guide.md`、`docs/2026-09-20-vrtc-code-change-plan.md` 文首唯一执行表、`docs/execution-prompts/README.md` 和 `docs/execution-prompts/task-dispatch-template.md`。再读当前票的合同、交付记录及实际变更。其余资料按需查阅，历史材料不作为当前派发指令。

派发者可提供“本次交付提交/范围、执行报告、指定票号”；未提供时从唯一表的首个未完成项开始，并核对工作区。不要默认最近一次 Git 提交就是实现交付；仅修改文档不意味着代码功能已完成。

## 审核步骤

1. **确定被审对象。** 检查适用 AGENTS.md、两个仓库状态、当前提交与目标票基线。明确哪些变更是本票、哪些是用户其他工作；修改文档前按公共合同保存相关 Git 基线。优先审查当前票及其直接前置，不无差别重审所有历史票。
2. **核对交付证据。** 对照票据验收，追到实际入口、消费者、状态/副作用与测试。分清“只有类型/文档”“已接线”“协议测试通过”“真实模型运行通过”。记录被测实现版本与待审实现是否一致；仅文档变化不要求重跑代码测试。历史日志可引用，但不能写成本轮实跑；测试数量或执行者自述不足以自动通过。
3. **检查范围和复杂度。** 沿用单票模板的依据与停止规则：新增字段、状态、导出、配置及重构是否服务当前合同或具体可达缺陷？纯未来设想不能成为下一票前置。必要权限/恢复不得以瘦身为由删除；兼容性按当前票合同核对，S4-E 未验收旧实验格式具名拒绝，不要求补兼容层。独立验收未覆盖的保证不能靠 prompt 声称成立。
   同时核对验收判据是否真的拒绝合同反例、所有必需检查是否影响最终 verdict；声明假设、无数字、测试全绿都不能自动证明语义正确。实验总账须包含失败和意外重跑，缺失记录明示，不能覆写成一次成功。
   按主 guide §1.4 检查职责归属：事实、行为、工具/prompt 消费者和旧实现删除位置是否清楚？context、通信、事后诊断、候选评估是否又堆入 task/runtime？新包是否实际接管主体、替换旧实现，依赖是否反向？同时区分默认相关性、读取授权和输出长度，不因减少上下文就禁止必要依赖读取。主体错位即记录本票设计/交付缺口，不能只看接口名字或行数。
   对本票触及的 400 行以上文件，按主 guide §1.5 和计划 E 节检查保留/删去/迁出/包内拆分的依据。不能以减行数替代职责收敛，也不能把持久事实误删为业务策略。查询路径须查明是否触发恢复、审批或闸更新；建议记录的开放性与实际应用的支持类型分别验收。
   本步仅核对 D/E/F 节已为当前票声明的迁移与删除，以及本票编号的职责收敛条件：新所有者的真实消费者是否接通，旧实现、生产调用、同名转发及重复事实源是否撤走，有状态协议是否仍只有一个写入者。未触及的文件不扩成全仓审计；不以行数、导出数或复杂度评分决定通过，也不为结构整理新增一票。返工须指出违反当前合同的具体调用链或反例，不能仅凭文件长而重开已验收的任务。
4. **处置实际缺口。** 只运行能解决当前疑点的必要检查，遵守环境与预算；不重复全量测试来增加信心，不默认调用真实模型、生产服务或 BB 工具。已有记录不足则保留待验收并列出缺失证据；确认违约则返工；外部条件缺失则阻塞。源码明确可达的缺陷有效，不必等真实事故；仅推测的问题不自动登记为必修补丁。
5. **核对复用与删除。** 按[计划五问复核](../2026-09-20-vrtc-code-change-plan.md#五问复核保留领域差异直接用现成底座)检查本票新增的通用机制是否已有 DSH 接口、是否有真实消费者；能删的配置/状态/转发随票删除。外部开源实现只有在接口、授权、持久身份及许可证适配被证实后才可直接引入；相似名称不是验收证据。不要因此重开无关的已验收票。
6. **更新一个事实来源。** 建设计划文首表同步当前票状态；新审核的详细证据按计划中的单项模板写入 `docs/history/`，从表中链接。主 guide 更新当前事实与相关缺口，受影响专项合同去掉过期当前态。历史实跑结果原样保留，新复核另记，不新建平行进度表。

状态决策如下，不得用文档调整制造通过：

| 核实结果 | 当前票状态 | 本轮准备的派发材料 |
|---|---|---|
| 验收及所需复核证据齐全，当前合同缺陷已关闭 | 已验收 | 唯一表中紧接的下一票，引用 D/E/F 已固定合同与验收编号 |
| 存在明确违反本票合同的实现 | 返工 | 当前票的定向返工 prompt，保留原验收，不另起“增强票” |
| 实现声明完成但关键证据不足 | 待验收 | 当前票的补验证 prompt，注明需要什么结果才能判定，不先派下一票 |
| 凭据、依赖或必要决策缺失 | 阻塞/待前置，按实际原因 | 写清解除条件；不产生貌似已可执行的后续实现票 |
| 当前票尚未实施且前置满足 | 待派发 | 当前票的实现 prompt，不跳到未来票 |

不要把所有旧验收自动撤销为待验收；只有新发现的具体反例、版本不匹配或本票依赖的关键证据缺口才重新打开对应项。独立审查未做就如实标明，不能让实现者的复述代替复核。

## 编写与交付

只准备一份当前可执行的实现、返工或补验证 prompt，按单票模板填写真实问题、前置、范围、验收和停止条件。已有相应 prompt 时更新它；没有才在 `docs/execution-prompts/` 建一个以票号/职责命名的文件，并在计划文首表和派发入口链接它。不要为一次审核再建目录、台账或工作流引擎。

派发前逐项核对承诺行为的真实入口、所有者、消费者、前置接口、正反例和拒绝/取消/恢复结果。阶段交接只安排施工先后；本票承诺的生产接线、迁移删除与验收须在本票闭合。交付方列作“已知边界”的每项都要指向冻结合同的明确排除或允许的具名拒绝；延后能力还须有后续票号。若属于本票承诺则判返工或待验收，不因写入下一票而放行。

派发材料须遵守公共合同的“子代理派发粒度”：整票由主代理负责，子代理各自只有一个子目标、必要输入和明确验收；不把研究、跨包实现、全部测试迁移及文档收尾塞入同一子任务。续跑只交接剩余范围。你本轮默认仍不实际启动或发送任务。

按单票模板的合同索引选验收编号，并填清整组完成所需证据，包括 A2-6、A4-5、EVAL-5、REV-5、EVO-5 中当前票对应的一项。D/E/F 的内部交接步骤不是子代理最大任务包：一步跨多个行为所有者时继续按接口交接拆小，主代理仍承担整组完成闸。A6 尤其不能整组转派，EVO-1 的真实 Agent 生成/恢复证据缺失时保持待验收；确定性接线通过不能代替它，也不自动授权收费实验。

第 9、11–14 项的架构合同已固定在计划 D/E/F，不再把“任选工具入口、触发源、候选种类或恢复语义”交给实施者。派发时引用对应输入/结果、失败/恢复与验收编号；先核对实际前置接口，一致就按合同施工。存在具体冲突才提出最小合同修订并同步唯一来源，不泛化重做设计、不照抄历史字段全集。私有文件布局和等价 helper 自主决定。

R1、R3、第 9 项 A2+A1 与第 11 项 A4 已验收。第 12 项 S4-E 经[返工复审](../history/2026-09-26-s4-e-rework-review.md)仍判返工；本轮 KISS 裁决后当前只派[简化收尾](12-s4-e-final-closure.md)，以计划 F.2 的现行合同复审，关闭后才可派第 13 项。第 10 项只留历史编号。R3 的原范围见计划 E 节，不扩大为全部 400 行文件的重写。未知失败由 Agent 调查与实验，不预建分类器、补丁目录或固定 supervisor 工作流。

同步文档时只清理本轮发现的重复/过时材料：当前入口修正文义；独有的决策、用户回答、验收和兼容记录保留；失效临时补丁或已被替代的重复内容可删除，但先检查引用并保存 Git 基线。归档文件标明历史状态，更新路径，不能以删除问题记录代替关闭问题。不因日期旧就删除 persistence-changes 或原始证据。

最终交付：当前真实状态与证据、已修正文档、唯一下一项及其前置、可派发 prompt 的路径（如存在）、未解决阻塞。检查本次文档链接、围栏、diff；纯文档修改不触发代码构建。默认不创建/启动任务、不向其他 agent 或外部系统发送派发消息、不推送或部署。

## 范围与固定场景

S1 明确交付、S2 错误根拒绝的有效历史证据保留，不默认重跑。只有本次必要生产修改影响了对应入口时才补有依据的回归，并明确区分历史版本证据与新版本证据。

S3 补验证沿用逐字输入：

```text
Create report.txt summarizing the quarter.
```

真实澄清工具的用户侧固定答复：

```text
No data was provided; state that explicitly.
```

该答复只确认未提供数据并要求明说，**没有确认某个季度，也没有授权“只用 checkout”作为通用数据来源**。不能为了通过实验偷偷换成更完整的答复。环境继续为空临时 checkout、隔离 DSH 数据目录、generatedTaskReview=off、evolution 默认 off；请求通过真实用户消息入口记录，满足 A0 来源合同，不伪造日志或绕过 intake。

本场景验收的是澄清及目标形成，不以业务根必须 verified 为统一要求：

- 若仍需季度/来源才能定义业务交付，必须继续澄清或明确保留未知，不能激活依赖未知值的季度总结目标。没有进展、工具报错、超时或什么都没做，均不能仅凭“没建根”判为通过。
- 若根据上述用户答复收敛为“report.txt 仅说明未提供数据”，可以激活该有限目标；契约不得夹带未经确认的季度、来源或事实，也不能声称已完成季度分析。若以此路径宣称交付成功，必须读取真实文件并由实际 verifier 验证该有限目标。
- 本票不要求 runtime 理解任意自然语言，不增加语义分类器。固定场景的判决由可核对的原始对话、契约和产物支持，允许显式的独立语义复核；不得用宽松关键词正则或实现模型自评代替。无法判定的轨迹记为 inconclusive，不能记 pass。

# 测试与证据工作流

## 红到绿

- 动手前先跑一次 `pnpm test`，记录失败清单；实现过程中每次只针对一个关注点，用单文件命令核对。
- 一个关注点全绿后再跑全量；全绿后跑 `pnpm build` 确认类型与打包未被破坏。
- 任何"通过"结论都必须来自刚刚执行的原始终端输出，而不是对代码的推断。

## 证据格式

命令原文、退出码、汇总行（`Test Files` / `Tests` / `Duration`）；失败时给出首个失败的用例名与错误。核对者应能用同样命令复现同一结论。

## 禁止

- 删除测试、跳过（`skip` / `only`）、放宽或改写断言来迁就实现。
- 用 mock 顶替正在验收的对象，或只验证桩而绕过真实路径。
- 用"应该可以"、"已经修好了"一类描述代替输出。

## 时间预算

本教程全量测试不到 10 秒、构建不到 5 秒；普通命令等待即可，不需要长任务通道。verifier 的时限配置（默认 600000ms）远超本教程所需，不会因超时误判。

## 问题和范围

prepare 已保存 champion 快照，但 apply 未确认生产 Skill 仍对应那个基线。两个候选基于同一版本产生，后应用的过期候选可能覆盖先应用的新版本。

只处理 `targetType: skill` 的单文件 SKILL.md。复用 P2 的内容身份语义和现有 prepared/champion 数据，不建立全局版本服务。

本票保证单进程串行调用以及两次调用之间发生的外部修改；不实现跨进程锁、并发 compare-and-swap、任意外部写入者与 apply 同时写的原子性，不修改现有 rollback 覆盖策略。把这些边界写进 guide。

## 固定行为合同

1. prepare 用同一次读取的生产文件字节保存 champion 快照及其 SHA-256 身份；不能分别读两次获得不一致的快照和摘要。原本没有文件，明确记录 missing。
2. apply 生产写入前比较实际生产目标与 prepare 身份：captured 要求普通文件内容摘要相同；missing 要求目标仍不存在。文件缺失、内容不同、类型改变或符号链接路径均视为冲突，明确拒绝。
3. apply 工具在人审前检查生产基线；服务在审批结束后的实际写入前复检。直接调用服务不能绕过。
4. 冲突不修改生产文件、不记录 applied，也不自动覆盖、merge、更新 champion 或改写原 proposal。提示基于新生产状态创建新候选并重新评估。
5. 拒绝后保留原候选、报告与历史记录。P2 候选身份和已有 replay 闸继续生效。
6. 新增持久化字段时保持旧 ledger 可读、旧 applied 可回滚；无法可靠证明生产基线身份的旧未应用 Skill 候选拒绝新应用，不能默认为匹配。

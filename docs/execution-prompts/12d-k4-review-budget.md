## 最小选择

## 固定入口与归属

1. 现有 reviewer 调用链核对的是自身剩余次数；原根已终态/用完 Run 数不阻止只读复盘。角色/读取域/真实来源校验不变。K4 用现有可触发的 review 源验收，A5 再替换触发策略和精确源协议；不要提前复制一套自动扫描。
2. 新增唯一工具 `task_budget_extend({requestKey, maxRuns})`，只给可信根协调会话，终态亦可调用；store 从会话绑定推导。maxRuns 必填，是批准后的总 Run 数正整数；不接受 deadlineAt、增量、相对时长、token 新账或 approved 参数。只允许提高已配置的有限 maxRuns；未配置表示无限，不需要扩额，直接拒绝。
3. 每次新请求必须经现有 DSH 人审展示 store、原总上限、累计用量、拟改后的总上限。工具/批准渠道接线在 agent-singularity，task-runtime 拥有校验及有效限额计算，Task 事件保存批准来源和扩额事实；runtime 不导入 evolution。服务消费可信批准渠道结果，模型和公开直调不能自填批准字符串越权。root grant 和 gate 只放行此窄入口，不开放业务写或通用 spawn。
4. 复用 Task store，增加一种预算追加事实；以 store+requestKey 幂等，保存原上限、批准后的上限、请求内容身份及批准引用。同 key 同内容返回已有结果，不再次审批/追加；异内容拒绝。批准后在 store 串行重检原上限，期间已被另一请求改变则本次拒绝，不能隐式重算授权额度。拒绝/取消零预算事件、零新 Run。
5. maxRuns 由部署配置和持久批准上限解析；重启不回退、不清空用量。公共解析器和所有准入/driver/replay 路径消费同一有效限额；历史 deadlineAt 可读但不参与新扩额基线比较或取消判断。已终态 Run 不重开。
6. 扩额只改变允许执行的资源上限，不隐式恢复/派发/创建候选、不提高工具权限。已有 replay 是本票执行消费者：次数耗尽时拒绝，人批准后可在原 store 开始实验新 Run；旧任务仍终态。A6 的新尝试以后直接复用此能力，不再造恢复专属预算或默认豁免。

删除 Agent 总时长配置/消费者、扩时入口及 reviewer 总时长 watchdog。不增加额度策略分类、自动审批、定时重试、成本预测或新平台。保持现有可执行硬限额与软观测的区别，不把 maxRuns 宣称成精确 token 成本硬封顶。

## 本次收敛：直接审批，持久计数（2026-09-27）

上一轮增量返工已中止；`25af727` 是未验收现场快照，不是交付。以下替换此前的实现方向，行为验收不缩减。不继续补摘要匹配、审批日志回查或缓存同步。

1. **扩额只有一次调用。** `task_budget_extend` 将请求和 DSH 提供的宿主执行上下文交给 runtime；请求仍只有 requestKey/maxRuns。runtime 校验根身份、派生 store、查幂等并私下冻结完整有效基线；随后调用初始化时装入的私有审批回调。`agent-singularity` 在构造期装配一次，回调用现有 DSH `approval.request()` 展示 store、整份原上限、累计用量和拟总额；仅实际 `allowed-once` 返回允许继续。未装配审批则新请求具名拒绝，不能默许。
2. **批准与提交不交还调用者接力。** 获批准后，在现有 store 写队列中再查幂等并比较冻结的完整基线，未变化才记事实；maxRuns 生效基线已变化则拒绝，重新调用须重新审批。公开入口不收 baseline/approvalRef/outcome，也不提供绕过审批的公开 commit。会话/工具 callId 取自宿主上下文，持久批准来源只是审计引用，不作为授权凭据。DSH 原生审批记录继续由 DSH 保存，不改其返回协议，不新增 receipt/token 服务。
3. **reviewer 只有持久 started 计数。** 扩大 ledger 现有每 store 串行入口：重新读取 started → 检查次数与既有触发条件 → spawn → beforePrompt 持久 started 并核对绑定 → spawn 返回后出队。等待 reviewer 输出和 Diagnosis 在队列外；队列内读写不再嵌套排队。未落 started 的失败不耗次数；已落行后派发/读回失败及取消仍耗一次，不退款、不假造业务 Run。重开从 started 重读，无计数缓存。
4. **必须删除。** 审批 binding/digest 授权、`reason.includes`、审批日志扫描、draft→审批→公开 commit 接力及其旧导出/调用方；reviewer 的 knownRows/persistedRows/claims/reserve/effective 缓存与预留/归还逻辑。请求内容身份用于幂等，持久完整基线用于重检，必要的零写查询继续保留；不能把这些事实误删成“不必要校验”。
5. **与 A5 的交接。** K4 只交付持久 started 计数和同 store 串行准入，不预建来源去重。A5 实现来源 claim 时，在其票内调整该入口，使同一区内先查已有尝试、需要新启动才读 started 并核算额度；claim 不作为第二份额度账。A5 的接口顺序不列为 K4 验收项。

## 交付与归属

父节点可以先委派调查，再根据结果实施或追加一批任务，最后主动提交自己的验收。不必预编完整流程，不经过 Evolution，不制造失败。`task-runtime` 拥有批次、写闸、唤醒与结算；`task` 保存提案/批次/Run 事实；`agent-runtime` 复用 DSH 唤醒；context 和工具只消费这些事实。

## 固定行为

1. 删除 Task 一生只能分解一次及子全终态后自动提交父结果的规则。同一父 Run 同时最多一个未结束子批次；父仍在等待、已提交、终态或有阻塞问答时不能新派。空批次拒绝。串行与现有准入/可选契约审核继续有效，不增加并行调度。
2. 批次结束后先确认子写入/受管理进程停止并归还工作区，再持久化父 `waiting_children → active`，解除批次写闸，通知原 Session。未解决问答仍单独阻塞写入；批次结束不能替问题作答。父可读结果、工作、追加一批或 `task_submit_result`；只有主动提交才做父独立验收。子失败也返回事实供父判断，不自动将父判成功；取消父/根及截止仍直接停止，绝不唤活终态。
3. 批次身份使用 `(parentRunId, proposalId)`；提案消费和绑定原子提交，重复 key 返回原提案/批次，异内容拒绝，不能用重复调用生成新批次。同 Run 同时最多一个待审核/待准入提案；晚到批准重检 Run、待处理提案和批次状态。删除固定 `b-<taskId>` 及按 taskId 猜当前批次的路径。
4. 一个 Run 的已准入批次成员按准入顺序累积，旧成员不覆写；父 `childEvidence.childIndex` 指该 Run 累积成员的稳定位置，不在每批重新从零解析。历史成员另属其原 Run。`dependsOn` 的批内索引保持批内；后批消费前批产物使用既有 Artifact/Evidence 引用，不造跨批索引语言。既有强制判据、失败成员和无效证据不得因新批次被过滤掉；本票不提供失败任务替换或改写 AC。根独立判据必须执行。
5. 普通执行、replay、显式恢复使用同一规则。批次结束持久化后、唤醒前重开，要能恢复同一父 Run/Session 并送达结果；已返回 active 的委派父也必须可恢复，不沿用取消全部未提交 worker 的分支。结果投递复用 A4 的来源/重投影办法，重复通知不能重复消费提案、写产物或提交。无法接管写入时具名停止。

## 删除与范围

删除自动父提交、一次性分解闸及失效 prompt/测试；不保留兼容开关或 old/new driver。保留唯一 verifier、现有取消/排空/预算机制；Run、批次增加不会重置预算。修改 Task 事实不意味着把 driver 移入 task。不建 workflow、计划 DSL、任务模板库、语义进展评分或万能 runtime helper。
